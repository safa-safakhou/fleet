# Controlled evaluation infrastructure

AR-P10 / PACT-180 and AR-F10 (including deterministic AR-F10-P plumbing), 15 October 2026. Source/offline acceptance only; real provider and behavioral experiment acceptance remain gated.

The fixed pact.evaluation-design.v1 manifest is mirrored in both repos. Six scenarios cover symmetric self-sufficient founders, complementary needs, overflow, bad trades, later legal Hall III development and Hall IV's unresolved ceiling. Development seeds 11/29 and held-out 47/83 are disjoint. The baseline, ten one-factor arms and three specified interactions produce 336 PLANNED independent world cells. A deterministic seeded rotation fixes balanced arm order before results. Every scenario/seed/arm requires a fresh database schema/world; matched solo controls require their own world. Two players sharing a world are a joint experimental unit, never two independent samples. Economics/politics are not enabled factors. Manifest changes require a new design version before observing results.

tests/evaluation/world.ts implements isolated world construction and refuses non-loopback/non-pact_test URLs and unplanned cells. It uses real onboarding/KingdomService activation, retaining founding allowances, all initial buildings, two builders and eight Home Guard. Scenario stock/economy differences are explicit synthetic setup before any decisions. Later development seeds sufficient stock and Farm III/Barracks III/Storehouse II; current ceiling stays 1,000 and no prior jobs/spends are manufactured. Six integration cases create twelve actual independent schemas, compare matched initial state and prove mutations cannot cross worlds. These are setup/isolation tests, not 336 executed behavior runs. The preceding real settlement versus solo test remains the reference material-benefit proof.

Fleet's strict EvaluationRecord/evaluate module groups scenario, arm, split and pinned configuration separately. It rejects duplicate replicas, mixed deterministic/real evidence, private payload fields, inconsistent stage denominators, unsupported-goal successes and claimed material benefit without authoritative readback and a solo control reference. It reports delivery/generation/validation/authority/commit/activation/fulfilment denominators, legal goal outcomes, actual fulfilled obligations, material benefits, justified waits, latency, reported tokens and original unknown allocations. Zero useful outcomes gives null cost-per-outcome, not zero cost. Unresolved owner/unsupported mechanic goals are excluded from eligible-goal failures. No reward for message count is defined. Input evidence must still be audited; a structured record is not cryptographic proof of a game outcome.

qualifyOutput has no network/provider capability: it validates supplied deterministic outputs against the actual closed schema, including native single-schema binding, unchanged 24,000-byte messages-plus-schema cap, and invalid action/argument controls. Diagnostics contain schema digest, field path and keyword only, never argument/message values. npm run eval:offline in either repository runs only these source fixtures. Existing engine tests separately cover both decision modes, restart, actual budget accounting, six growing-memory rounds, exact reference refusal and optional social handoff. VW remains unused and thinking settings are untouched.
