# Source-complete research context

`source-complete@1` is an explicit opt-in for new research recipes. Existing `observed-pact@1` and historical cognition/specialist packets retain their preparation. The compiler seals the selected components; saving configuration starts no execution.

The kernel adds mandatory current owner guidance, authorized fresh observation, original pending-command identity and recorded rejection feedback when present. Optional typed memory comes from the declared retrieval strategy. The assembler preserves truth classes and contradictory sources, ranks by explicit source priority with stable ties, and omits optional records whole with reasons. It never truncates mandatory facts, splits UTF-8 or calls a helper model for compression. Insufficient capacity refuses with `CONTEXT_CAPACITY_REQUIRED` before native model allocation/dispatch.

Packets record exact ordered messages/schema, separate byte counts, tokenizer identity and source spans in UTF-8 **message-content** coordinates. Worker-prepared messages are labeled working state; they are not upgraded to verified owner/world evidence. Exact injected tokenizers and the default labeled UTF-8 estimate are distinguished. Estimates do not certify a model's token window; native provider admission remains authoritative.

The private lineage artifact is linked to retrieval coverage and the final model request. Tracked providers must emit preparation before dispatch. O3 compares the actual prepared messages with the assembled messages, records serializer/schema transformations and their accounting, and rejects hidden message changes or excessive final capacity before dispatch. The final provider-prepared event and dispatched event retain causal links to the original lineage. This observes actual wire preparation instead of relying on a parallel displayed summary.

Synthetic tests preserve mandate, fresh Unicode facts, feedback and an exact pending command; test impossible capacity, repeat digests, optional omissions, expiry, native accounting and downstream message mutation. Real-provider/model quality and installed-runtime acceptance remain separate.

Source-derived context artifacts inherit source retention and revocation. Provider evidence and broker model results reference that packet; source-complete checkpoints inherit their recorded step results. Already delivered bytes cannot be retracted, while later reads and restore of expired evidence refuse.
