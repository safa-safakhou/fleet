# Private evidence storage v1

Artifacts use at most 1 MiB plaintext chunks, existing authenticated Vault encryption, and AAD binding the complete original scope, artifact ID and chunk index. Only ciphertext digests are stored; no public plaintext hashes or secrets are emitted. A dedicated 0700 filesystem root and 0600 files reject symlink/traversal paths. Temporary files are synced and atomically linked without overwriting published chunks.

Ordinary capture reserves a finite run quota before IO and publishes its manifest only after all chunks and expected byte counts agree. Interrupted/truncated/failed capture keeps an explicit partial manifest. Native transactions may instead commit encrypted chunks and their complete manifest atomically with original intent, then materialize that bounded ciphertext outbox after commit. Reads remain available from authorized encrypted storage while materialization is pending. This avoids network/filesystem IO in native intent transactions and avoids losing payloads between commit and publication. Ciphertext outbox data is erased only after successful publication or policy deletion.

Private observation expires after 30 days. Consent carries a monotonic database version: false→true does not resurrect data captured under an older grant. Permission is checked per artifact and before each delivered chunk. Revocation/expiry tombstones the manifest, clears pending ciphertext and deletes files; it never removes model reservations or command recovery records. Derived stores register deletion hooks with the retention coordinator. Unknown filesystem ciphertext is reported for reconciliation, not automatically erased as if it were disposable evidence.

Back up Fleet SQL, the artifact root and the separately protected Vault key together; validate scope/count/ciphertext integrity after restoration. Do not put any of them in Git or logs. The SQL metadata is authoritative for status and quota; ciphertext byte counters describe encoded storage, not exact filesystem block allocation. No world or service is backed up/modified by implementing these modules.
