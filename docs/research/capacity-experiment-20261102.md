# 24-kingdom capacity experiment: stopped with unknown usage

The owner subsequently selected vLLM; the six-replica Ollama proposal below is superseded. [Current switch, measured startup failure, repair and storage condition](vllm-metal-switch-20261102.md). Historical usage/effects and closure proofs remain unchanged.

The higher-capacity attempt launched at **14:36:01 UTC on 2 November 2026** and closed at **14:38:23 UTC**, with its world paused at tick 2. The hour did not complete. [Exact record and per-kingdom outcomes](capacity-experiment-20261102.json), [preserved attempt record](capacity-attempt02-20261102.json).

Eight native turns started: five finished with validated WAIT decisions and fully reported usage; one reached its model deadline and two other dispatched calls were interrupted by safety closure. The latter three have unknown final usage. Their **120,000 reserved tokens remain held**, with null measured usage. The five reported calls consumed 52,980 input and 1,221 output tokens. There were **zero gameplay commands**. Sixteen kingdoms had no native turn before closure.

## Confirmed cause

Ollama 0.40.11 reported `model architecture does not currently support parallel requests` for Nemotron's `nemotron_h` architecture. Its runner initialized **one inference slot**, despite `OLLAMA_NUM_PARALLEL=8`. Fleet reached four simultaneous native allocations, but these were queued at a single inference slot. Configured HTTP concurrency did not provide parallel inference. One request exceeded its existing deadline, triggering global closure; stopping the remaining active requests left two further missing final usage reports. Increasing timeouts would hide this capacity mismatch.

The source/runtime changes did remove Fleet's serial operator bottleneck: 24 long-lived manual Temporal workers shared one runtime and a 16-connection pool; fresh binding ownership covered event and periodic tasks, with per-binding exclusion. Initial packets fitted at a maximum 42,047/48,000 bytes without preflight inference. The attempt used 8 scheduled, 8 event and 8 hybrid agents, a two-minute periodic cadence, and the recorded fresh budget envelope. These mechanisms did not establish backend throughput or gameplay effectiveness.

## Closure and preservation

All owned execution, provider, rules, awake and watchdog processes stopped; running native turns, active worker sessions, capacity leases and pending commands are zero. All four database snapshots were independently restored, matching **328 table projections**. Restored evidence reads verified **623 artifact references / 15,223,120 plaintext bytes**; the state copy matched **135 files / 24,089,739 stored bytes**. All 208 encrypted observer pages passed authentication, sequence, hash-chain, scope, consent-version and retention checks.

Five recorded task runs have complete coverage. Three remain explicitly partial because final model usage is unknown; their expected artifact bytes are all retained. Preservation checks found no differences across 67 original container configurations and 115 volume definitions; the three original services remain healthy. No allocation was refunded, task replayed, historical budget edited or service restarted. The accepted historical 16.29% latency result still fails the original 10% qualification limit.

## Replica repair and next run

The proposed successor uses up to **six separate, identical Nemotron servers** behind a local single-attempt router, with measured admission at 2, 4 and at most 6 concurrent calls. Each backend remains one-slot. The router preserves request and streamed response bytes, pins the model, records metadata and request digests, refuses excess work before dispatch, propagates failures without retry, and quarantines disconnected replicas until restarted. Seven targeted tests cover overlapping physical fake backends, limits, failed capture, cancellation, exact streaming and no fallback. Router source is committed as `760a0bb`; all 1,294 root unit tests pass with 23 skips, together with types/style/build/boundaries/generated contracts. Existing 405 warnings/83 infos and the bundle-size warning remain. Private six-server operator templates pass syntax and independent watchdog self-tests; end-to-end operator qualification is still required. This is source verification; real six-replica throughput is unproven.

The successor must retain the native authority, accounting, validation, observation, consent and recovery guarantees, the 10 GiB disk reserve, finite one-hour window and final three-minute admission cutoff. Increase only when measured latency and available memory support the next level; GPU contention may impose a lower useful limit. Post-verification host space is 10.74 GiB, only 0.74 GiB above the unchanged reserve. Before a new launch, recheck recording headroom against the finite envelope; the current measurement does not establish enough storage for a completed hour. Add an admission drain that lets already dispatched turns settle before an ordinary operator stop, while retaining immediate safety closure for unknown usage or preservation failures.

**No successor is launched or sealed.** The existing safety protocol requires resolving unknown usage before another real retry. The owner has been asked whether the three untouched holds may be carried forward while a separate fresh experiment runs. Until that answer or authoritative usage resolution, further real calls remain blocked; source verification and preparation can continue.
