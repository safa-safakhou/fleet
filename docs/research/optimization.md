# Bounded research optimization

A4 adds a reference DSPy 3.4.1 BootstrapFewShot optimizer and MLflow 3.17.2 metadata projection. Install the locked optional research environment with `uv sync --project workers/research --group dev --extra optimization --frozen`. Run `npm run optimize:offline -- --fixture` with Fleet's pinned Node toolchain. The CLI creates and removes its own synthetic database, uses recorded providers, and preserves encrypted evidence under an ignored private `.state/research/offline/<id>` directory.

The reference optimizer shuffles frozen training cases with a recorded seed, attempts one bootstrap round, selects at most two demonstrations, and reserves every actual teacher call through the native evaluation grant. Copies of the DSPy LM share the same call counter; failed attempts consume budget, and there is no automatic provider retry. Training plus development has a shared limit of 16 actual calls and 1,000,000 reserved/known tokens. Each native turn retains its three-call limit. Unknown dispatch/usage is never assumed free. The Python bridge has no provider credentials and only a scoped broker socket.

The optimizer sees train/development data and public split fingerprints. Heldout file loading is refused by its dataset API. Family/world/input-hash overlap is rejected before any split opens. Candidate export freezes module/signature/instructions, demonstrations, dataset digests, seed, framework version and native allocation/result lineage. The registry verifies training-only demonstrations against the host's frozen dataset and native teacher allocations, checks a trusted C2 capability fingerprint, and saves an experimental manifest whose build digest pins the candidate. It has no activation method.

After export and development validation, a separate host claims the frozen heldout digest before dispatch, preregisters baseline/candidate runs, then evaluates each heldout case once under separate grants. The registry regrades the native output artifacts against the frozen independent rubric, ignoring framework pass/score claims. A durable digest claim prevents another candidate or failed assessment from reusing that holdout in the same authoritative installation. Reuse requires a new independent holdout/version. Fresh disposable fixture databases intentionally allow reproduction of the synthetic protocol; they confer no real qualification.

Assessment requires complete native lineage, known usage, bounded actual calls/tokens and admitted context. It records accuracy, resource details, integrity gates and sample limitations. Even a positive descriptive delta requires independent review; active profiles never change. Copied private candidate/assessment bodies are encrypted, linked to all teacher/development/heldout source artifacts, and invalidated by source expiry, deletion or consent withdrawal. Maintenance clears expired controlled copies; minimal digest claims remain to prevent holdout reuse.

MLflow is a replaceable projection after authoritative publication. The native adapter sends only pinned metric scalars, allowlisted methodological parameters, digests and opaque references. The Python adapter uses an explicit owned local SQLite store, disables autologging, and never uploads prompt/output artifacts. Snapshot digest identifies one run; completed resync does not duplicate metric history. Outage records an unavailable sync status and leaves the encrypted experiment intact. Retry is explicit through the same adapter. Metadata is not a substitute for the authorized native comparison; missing values are omitted, and run-mean scalars are labelled descriptive-run-mean rather than inferential estimates.

The worked seed-42 fixture has two teacher calls, two demonstrations, 8/8 development and 2/2 heldout for both baseline and candidate: 14 native allocations, zero real calls, delta zero, **no demonstrated improvement**, no promotion. One shared synthetic world cannot establish superiority. Native C2 compilation, encrypted archives, real Promptfoo/DSPy execution and actual idempotent MLflow logging verify the integration, not model quality or gameplay effectiveness.

The pinned DSPy 3.4 custom `BaseLM.forward` interface is supported but deprecated for removal in 3.5. The bridge is isolated; an upgrade must replace it and repeat boundary/usage tests. Optional optimization dependencies are installed in the research environment, not the base acting-worker image. The trusted host optimization harness is not an adversarial Python sandbox or a deployed container/IPC acceptance certificate. Real providers, weights, retained data, live enrollment, installation and later U/Q work remain outside this assignment.
