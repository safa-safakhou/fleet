# Research memory and index privacy

Typed memories are encrypted, scoped projections of authorized native sources. Peer statements, inferred beliefs, command admission and observed completion retain distinct source classes. A receipt is not automatically promoted to completion of future construction or delivery. Kernel-only source registration is separate from worker capture; optimistic revisions preserve prior versions and source lineage.

A namespace binds world incarnation, actor, binding, participant, profile, memory component, language and embedding identity. Raw records and original evidence remain distinct. Indexing needs both current observation consent and a separate persisted grant matching the sealed manifest; no live indexing consent has been granted by this work. Grants are trusted installation ports and are not agent RPCs.

FTS lexemes, approved projection text and vectors are **plaintext derived information**. Database owners, superusers, disk and backup readers can infer their content. RLS does not protect against those principals. An installation enabling private indexes must separately approve its disk/backup encryption, access and deletion policy. Encrypted raw evidence does not make an index encrypted.

Projection queries run under `fleet_research_index`, a non-owner, non-login, non-bypass role with SELECT only and FORCE RLS. A kernel-authenticated transaction issues an unguessable ticket bound to its transaction ID and namespace; setting an actor GUC cannot mint authority. Tickets are removed before commit and local settings reset on commit/rollback. The role cannot read raw memory, grant or ticket tables. Transaction snapshots hold consent locks until the authorized query completes; later queries observe revocation. No foreign candidates or counts are fetched and filtered in the UI.

Revoking observation consent removes raw derived memories, sources and grants atomically. Revoking indexing permission removes searchable projections while leaving still-authorized encrypted memories. Source expiry/revocation removes dependent memories and indexes through retention triggers, with eligibility checked again on reads. Original accounting/recovery data follows its existing policy. Ordinary PostgreSQL supports baseline/FTS; vector strategies require the reviewed pgvector extension and fail explicitly when unavailable.

Copied private evidence inherits its source deadline through native artifact dependencies. Source expiry/revocation invalidates dependent memory/retrieval/context/model bodies and source-complete checkpoints, without retaining a fresh30-day copy. Rejected-source capture rolls back its private artifact. Minimal evidence/accounting identities remain; maintenance purges invalidated ciphertext. Kernel composition owns these dependencies; external game source identifiers retain their native freshness/retention semantics.
