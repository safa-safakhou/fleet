# Autonomous specialists: source and operator contract

This is an uninstalled source implementation. Offline fixtures establish mechanisms, not production behavior. Real-provider qualification and rollout remain separate gates. The retained world is paused and was preserved by non-access.

Use the Engines & reports launch wizard, authenticated launch API or `fleet` CLI. Select an exact architecture version, use the existing account/model configuration, save an inactive draft, check it, then explicitly start its reviewed digest only under an execution authorization. Editing the draft invalidates readiness. The catalog currently contains six families and seven registered exact versions; the unregistered packing candidate `reactive-cognition@1.1` is excluded. Old `@1` profiles do not acquire new skill behavior.

New `autonomous-specialists@1` drafts default to learning enabled and advisory skills. The PACT two-role preset contains resources/diplomacy; `full` adds development/defense. All roles use the cohort model, share its native compute allowance and canonical action lane, and keep separate scoped goals and memory. Owner priorities affect admission; peer prose grants no authority. At most eight messages per envelope, depth four and two material conflict revisions are supported. No mandatory alliance, message or action-volume objective is imposed.

PACT supplies the new profile's explicit `specialists@1` input policy. At24000 bytes it preserves mandatory current own stock, authority, construction/training facts and whole requested answers; large derived briefing/full-rule text and omitted pages are marked unavailable and require scoped reads. The frozen negotiation controls retain their own policies. Essential history or a requested answer that cannot fit stops before inference; no packet allowance is increased. Only an adapter-advertised specialist policy is used in another environment.

PACT must explicitly advertise `fleet.action-effects.v1` through the default-off API/MCP extension, and Fleet must explicitly select the matching protocol. The supported matrix is [eight actions](../../pact/docs/implementation/agent-action-effects-matrix.md) in the paired PACT repository: contact request/answer, messages, building/training queues and supply offer/counter/sign. Quotes are read-only. Native SERIALIZABLE admission rechecks exact source, authority, stock, peer consent and expiry. Unknown commands retain reservations and recover only their original receipt. Military/garrison/cancellation are not in this matrix. The older specialist coordinator requires its separate coordination protocol; effects support alone does not make it compatible.

Guarded skill mode requires finite `nonModelLimits` (`reads`, `actions`, `messages`, positive `steps` and `wallTimeMs`) persisted by the same launch spec, plus reviewed adapter primitives and fixture classes. No automatic allowance is synthesized. Limits accumulate across roles, invocations, events and fallback turns; they are not reset by retry. Read units count authorized observation/bootstrap bundles and quotes, not individual underlying HTTP or SQL statements. Quote and post-quote owner reads are separately charged. Validation reserves its bounded worst-case time before running; actual time or unknown measurement is reported separately. Persisted waiting consumes wall time. Original receipt recovery is labelled safety bookkeeping and cannot grant a replacement action.

The first action-producing PACT template is `evaluate_offer_for_existing_supply_goal@1`. It only uses exact parameters from a prior active goal: offer/version, counterparty, complete native terms JSON, ordinary internal-unit reserve minima, and a GAME-time assessment deadline. Terms use the published command schema, with no inferred defaults. It requires the exact peer's existing signature and checks the current owner intent. It cannot choose a new price or recipient. Native guard floors cover full outgoing exposure and exclude promised incoming stock. After signing, it waits separately for actual deliveries/default and only records a completed goal after all agreed installments are observed without failure or overflow loss. Receipt, procedure completion, economic benefit and general strategy remain different claims.

Skill bodies and versions are immutable. Publication is explicit; a same-binding compatible recipient must explicitly adopt that exact version. Source deletion/expiry or consent removal withholds private content; invalidating a pinned child suspends dependent parents. Changed registered primitive/environment/policy dependencies invalidate executable qualification. Current goal/authority/stock changes are dynamic guards, not a permanent permission grant from a passing fixture. Unsupported action recipes remain advice. Qualification has host provenance and seven synthetic guard/restart cases; a model's self-rated success cannot promote a skill.

Inspect `/api/instances`, `/api/instances/:id/specialists` and `/api/instances/:id/skills` through the existing operator session. The console shows bounded retained snapshots of state, wake/conflict data, deliveries, original evidence, actual delivered-evidence trace IDs, skill qualification, learning allocation lineage, work reservations/actuals, original receipts and later outcomes. Refresh to obtain another snapshot; consent changes invalidate the displayed snapshot. These routes have no model/game port. Their shareable scope omits private identities, goals, messages, evidence and bodies. The private view is capped at four roles and32 recent records per section; coverage is explicitly incomplete. Raw model and peer text is escaped and untrusted.

`evaluateSkillReuse` reports all acquisition, validation, retrieval, execution, monitoring and fallback costs, actual versus reserved usage, outcome coverage and regressions. Missing baselines/tokens/timing stay null. Its first observed amortization prefix is not a forecast. Authored fixture timings are labelled simulated; real savings and quality remain unqualified.
