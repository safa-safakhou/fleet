# Design decisions and their reasons

These decisions explain the current source, not a list of features all enabled in a deployment. Original specifications own product behavior. This narrative does not alter rules, grants or current cohorts. [Evidence index](references.md).

## Preserve the loop while adding alternatives

The founder questioned whether simultaneous building completions and peer messages should share one undifferentiated model context. Replacing the controller immediately would erase the baseline and confound comparison.

Decision: versioned engines coexist. Existing cohorts keep identities/configuration; fresh eligible cohorts explicitly select an engine. Consumed profiles are immutable. The legacy path stays available while reactive/cognitive paths evolve. Replacing a blocked identity or changing its architecture is not recovery.

## Separate trigger, architecture, model and environment

A timer determines when work is reviewed. Events identify changes. An engine organizes reasoning. A model supplies inference. An environment defines facts and actions. Changing all five simultaneously makes apparent improvements hard to explain.

Decision: record environment capabilities, engine references, wake policy and model/settings independently. Timer/event work shares the parent allowance. Comparisons/reports are optional; the playable fleet is the product, not a mandatory research study.

## Let survival and relationships matter without prescribing personality

Scarcity, threats, obligations and other kingdoms should have consequences. Communication, alliance, refusal, silence and aggression can each be reasonable. Mandatory messaging or a universal trust score would put the desired behavior into the measurement.

Decision: expose authorized capabilities, needs, dependencies, threats, terms and outcomes. Models can form cited subjective beliefs and choose responses under owner authority. Preserve alternatives and uncertainty. Existing rules supply consequences; no reward for alliance, message volume or verbose thinking was added. This is observable behavior design, not a consciousness claim or proof of a survival instinct.

## Use coordinated proposals before independent execution

Five changes do not automatically justify five unconstrained writers: they can spend the same resources or make conflicting promises.

Decision: F6 implements at most two focused proposal workers and one coordinator under the same parent allowance, selecting one next command or abstaining. An independent-submit broker was compared only with fakes and is absent from runtime registration. The environment must validate declared complete effects and atomically enforce expected revision at commit. PACT does not implement that protocol, so F6 is refused before inference.

Structured resource/authority conflicts can be checked; diplomatic consistency remains a model judgment. Provider capacity and environment permission are separate gates. More workers do not mint tokens or authority, and remaining concerns need later eligible tasks.

## Separate world truth from interpretation

A promise is not fulfilment; delivered help and a lost battle can coexist; a queued build is not completion; no observed event is not proof that no event occurred.

Decision: PACT supplies authoritative dated facts and receipts. Fleet keeps originals separate from interpretations, predictions and plans. Updates require owned, retained and actually delivered sources. Confidence remains subjective, not calibrated probability. Agents cannot approve their own human exceptions or alter another player's private state.

## Recover without erasing failures

One unusable model answer should not break an ordinary agent. Blindly retrying uncertain spend or a possibly committed action creates hidden cost and duplicate effects.

Decision: allow one metered correction for known completed unusable output. Preserve every allocation and response. Known noncommitting failures can replan within limits; unknown usage needs its exact review; uncertain commands reconcile their original receipt; authentication reconnects the same account when authorized. Terminal runs remain terminal. Never reset counters, substitute actors or relabel historical failure as success.

## Use conservative, immutable grants

Reported usage can be smaller than the reservation or missing. Reads, helpers and corrections are real work. A new approval ID must not silently reopen an old grant.

Decision: reserve before dispatch, separate reported from allocated tokens and retain unknowns. Qualification pins source/time/model/scope and append-only lineage. The diagnostic uses a unique database registration plus an exclusive fsynced, hash-chained encrypted journal. Shared budget/deadline/uncertainty fences stop both modes. Unused allowance is neither refund nor future permission.

## Inspect what was delivered and what actually happened

A stored memory can miss the model context. Valid JSON can contain false arithmetic. A receipt can confirm admission without eventual benefit. A heartbeat can coexist with all actors blocked.

Decision: inspect proposal, accepted update, retrieval candidates, final packet, decision, receipt and material outcome separately. Record queue delay, omissions, exact usage and per-actor completed turns. Neither uptime nor message/action count ranks intelligence. The latest diagnostics demonstrate these distinctions in actual evidence.

## Separate install, model qualification and activation

Decision: verify backup/restore, disabled rollback and maintenance fencing; install with execution off; qualify exact provider/engine protocols; then separately approve a small environment-matched run. The local artifact was installed disabled. Later fixes were exercised in isolated harnesses without switching that artifact or touching server Fleet.

## Keep a future fresh world recoverable

The 100-Luna/local-group proposal would provide activity and product comparisons. An in-place wipe risks losing history and binding old credentials, memories and pending commands to a different world.

Proposal: a new world/database generation with immutable identity, verified old-world archive, disjoint cross-host roster, normal enrollment, measured founding baselines and explicit budget windows. A supported world-switch/reset operator, stable authorization renewal and measured throughput remain prerequisites. Publishing documentation is not reset or population authorization.

## Limits of architectural comparisons

One model across local groups can compare engine packages, but a cognition bundle does not isolate beliefs alone. Luna versus Nemotron changes model, host and route too. Kingdoms influence each other and are not independent replicas. Founding time, threat/reply exposure, helper path, budgets and source revision matter. A larger explicit allowance can prioritize outcomes; spending more is not itself evidence of a better architecture.
