# Accounted model-output recovery — 18 October 2026

Founder requested investigating the Nemotron failure and ensuring a single failed model answer does not break the system. This is a local source/offline repair. No server/game contact, deployment, new provider run, population, budget increase, historical recovery review or delegation.

## Cause

The earlier native Ollama controls recorded two thinking=true failures with done=true/stop, nonempty thinking, empty final content, and just 64/28 generated tokens. They were not output-limit exhaustion. Merely describing the schema in the prompt did not prevent them. Thinking=false passed its separate eight-call control; that is not permission to toggle an existing run.

The exact pinned [Ollama v0.35.1 native chat route](https://github.com/ollama/ollama/blob/v0.35.1/server/routes.go) passes the parser's thinking-close marker into completion. Its [llama-server bridge](https://github.com/ollama/ollama/blob/v0.35.1/llm/llama_server.go) wraps a supplied JSON schema with [thinkingGrammar](https://github.com/ollama/ollama/blob/v0.35.1/llm/gbnf.go). Every thinking-prefix rule contains an empty alternative: generation may end before the closing marker and before final JSON. The [upstream test](https://github.com/ollama/ollama/blob/v0.35.1/llm/gbnf_test.go) explicitly asserts that behavior. The Nemotron parser keeps text in the thinking channel until its close marker. Thus schema-constrained native output does not guarantee a final answer when thinking is enabled.

This is a verified contract gap in the exact provider source, consistent with our recorded failures. The original Q1 did not retain sampled token IDs or thinking metadata, so its exact token sequence cannot be reconstructed. No confirmed drop-in upstream upgrade was established; other-model GitHub issues are not certification of a fix for this route. Removing the grammar's empty alternatives or exposing a strict-final option is a candidate upstream change requiring a provider build and separate qualification; it is not installed or claimed verified here. Fleet must tolerate unusable answers regardless.

Fleet had a separate resilience gap: legacy controllers already correct malformed output within their turn allowance, but generic reactive/continuity/coordinator admission returned the first unusable answer without correction. Q1 v1 was also deliberately fail-fast. Those paths needed bounded, metered recovery rather than an untracked retry in the HTTP adapter.

## Repair

`HttpModel.decide` still makes exactly one execution. New `recoverModelOutput` performs at most one corrective attempt only for completed answers with known nonnegative usage and MODEL_THINKING_WITHOUT_FINAL, INVALID_MODEL_OUTPUT or MODEL_OUTPUT_TRUNCATED; supplied JSON schemas are validated too. Each attempt enters ModelAdmission independently, acquires route capacity, checks the current claim/environment deadline, and reserves/settles a separate original-ledger allocation. A cancellable 100 ms delay separates attempts. Existing call/token/input/output/deadline limits remain unchanged; atomic reservations win races.

The corrective instruction asks for a complete final JSON answer, preserving the original task, peer facts, schema, model and explicit thinking mode. If that instruction would overflow input allowance, retry retains the exact original packet and records that correction was omitted. No evidence truncation, mode switch, reasoning promotion, permission expansion or command replay is added. Provider safe completion metadata and the retry's cause/attempt are recorded in existing consent-controlled encrypted debug traces. Internal reasoning is not captured.

Workers preserve space for their admitted sibling and the coordinator; an atomic floor prevents competing retries consuming those slots. A known unusable worker output can abstain while healthy workers continue. If failed outputs leave no proposals, the task reports MODEL_OUTPUT_RETRY_EXHAUSTED and waits until its original next scheduled turn. A malformed answer after the last corrective attempt likewise waits for a fresh scheduled attempt; it does not mark an ordinary agent terminal. An exhausted finite total budget remains exhausted. No continuous busy-loop or extra allowance is created.

Unknown usage, ambiguous transport after dispatch, overrun, authentication, authority and prompt-mode conflicts do not become output retries. Existing same-account recovery/dependency/backoff and original-receipt reconciliation remain authoritative. Unknown model spend cannot be guessed, and uncertain game commands cannot be resubmitted. Other agents and worker supervision retain their existing independent behavior. Legacy engine and golden baseline files remain byte-identical.
