## Runtime and ownership

Add explicit fresh-binding Temporal enrollment, binding one immutable manifest/profile to every subsequently created task for that binding. Existing exact-key routes remain supported; reject conflicting manifests/profiles and consumed enrollment. Native EventIntake retains category/group task keys, cursor/dedup/quiet/resync/deadline semantics; do not collapse unrelated deadlines into one invented global key. New tasks inherit ownership atomically. Ordinary workers cannot claim them. Manual worker delivery means all24 workers remain ready, but the operator sends at most one new wake per binding and at most the current global slot count. Every native execution still has fresh claim/fence/turn and exact scoped evidence.

Select eligible tasks with deadline urgency and fair actor rotation, preserving independent per-binding eligibility. Record trigger→ingest→eligible→dispatch→provider→decision→receipt timings separately. Skip neither queued nor refused work in metric populations. Native deadline checks remain authoritative; a stale event is a measured scheduling miss, not permission to replay it. Definite model/proposal failures are retained and can quarantine that binding; unknown usage/commands, failed capture, service/process loss or resource/clock/window breach close admission globally. No automatic retry of failed tasks.
