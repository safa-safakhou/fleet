# LLM-centered continuity in Fleet

Fleet's optional `cognition: "llm-centered-v1"` model setting adds episodic memory, persistent intentions, reflection and revisable beliefs about other players. The LLM remains responsible for interpreting the situation, forming plans, negotiating and choosing each read/action/wait. No building/contact reward or focus selector directs this mode. VW is not wired into the runtime, is no longer offered in configuration and new VW selections return `VW_UNUSED`; historical source/journal rows are preserved.

Choose **LLM with memory, reflection, plans and beliefs** when configuring an unconsumed fleet. Saving a setting enrolls no accounts and initiates no inference. Existing consumed configurations, identities, counters, unknown records, schedules and releases are not rewritten. The founder subsequently authorized [local rollout to the existing five Nemotron agents](cognition-local-deployment-20261013.md), using a separately audited migration that retains their consumed history and budgets. The server fleet is unchanged.

## Turn lifecycle

1. Read authenticated current game facts and the agent's available exchanges. The game adapter produces a small dated observation and observed peer IDs. Fleet captures actual delivered messages/agreements and actual command receipts in a separate encrypted episode journal, scoped to this one agent. Peer statements prove only what the peer said.
2. Retrieve account-owned experiences using relevance, peer relevance, recency and importance. Always include the current observation, a relevant incoming peer statement and a verified unreflected result when available; return a bounded set of other episodes, the persistent plan, relevant beliefs and recent reflections. Missing/expired sources and partial bodies are explicitly labeled. `fleet_memory_recall` lets the LLM request a specific question about its own history through the normal decision allowance, without inference of other players' private history.
3. The LLM returns an envelope with **cognition first, decision second** in its normal answer. The final user input places cognition last for attention to the actual source. Fleet offers a small `analysisOpportunities` packet derived from the **final delivered evidence**: `peer_evidence` for a tentative inferred/alternative peer motives anchored to an exact supplied cue, plus a concrete expected peer response; `recorded_result` for an exact supplied observed fact followed by an explicit intention/result difference, causal lesson and concrete next step; `tested_prediction` for reassessing a saved reply test with a quote from the new reply. The provider schema supplies the exact cue as a literal, removing quote-copying bookkeeping; the model writes inferredMotive, alternativeMotive and expectedPeerResponse. The model may choose `none` with a specific reason when nothing warrants learning. Invented quotes are rejected against both the full owned source and its visible excerpt. A prediction states an observable interaction, not confidence metadata or the owner's building goal. Fleet resolves the offered alias to the exact source/peer and fills future test times and recorded outcome bookkeeping; the model writes all subjective judgments. Optional plans and memories still cite delivered IDs. The canonical source-linked update format remains compatible with existing clients/journals. There is no extra reflection/planning model call, forced conversation or inference initiated by incoming messages. Learning means retaining experience and revising beliefs/plans in context, not updating Nemotron weights.
4. Fleet validates update size, expected version, actual delivered evidence references and observed peer IDs. New peer beliefs also require a typed basis that belongs to that peer and is visible in this exact input: incoming statements/replies, or authoritative contact/agreement facts. Outgoing messages and self-authored receipts cannot establish another player's behavior. A concrete prediction has a reply/agreement test and future game-time window. Agreement support also requires the authoritative agreement event time; observing an old agreement again cannot fulfil a new prediction. Only the same previously saved prediction/test can become supported, with an actual matching reply or observed agreement inside that window; support applies to this narrow observable event, not the whole hypothesis or reliability. Missing replies and contrary statements remain unresolved rather than fabricated failed tests. New confidence is limited to low/medium because these sparse sources do not justify calibrated high confidence. Interpretations cannot be used as independent corroborating evidence. Sources are rechecked against this agent's retained journal at commit; foreign/expired/invented references are refused. State/update/interpretation writes are atomic, fenced and idempotent for the turn/decision. A conflicting replay is rejected. An optional cognitive-update error is visible and does not authorize or silently replace the game decision.
5. The original game permission/schema/preflight/lease/receipt pipeline executes any chosen commitment. New reflections submit only an existing outcomeRef, source references and a concrete revision; Fleet fills the recorded intention and factual result from its owned journal. A later incoming reply can also be reflected on against a previously saved, actually delivered reply prediction and its time window. Its quoted statement remains a claim, not a verified agreement or delivery. They cannot claim the same proposed command already succeeded. Confirmed command admission is distinguished from later completion, agreement or delivery. Pre-submission refusals are captured as explicitly not-submitted controller results; uncertain submissions do not create a result. Proposed commands and subjective plan completion are never recorded as committed gameplay. A saved plan is an intention, not a queue; every future action is freshly decided and validated. Unknown model usage and pending commands retain the existing admission/recovery rules.

For cognition mode, the provider output schema requires the usual wait/read/action decision plus `cognition.expectedVersion` and `cognition.review`. The controller still accepts legacy optional updates; existing journal entries are unchanged. Its expectedVersion field is constrained to the actually delivered state version; citation/player enums are constrained to the final delivered non-interpretation evidence and observed peers. The fitter counts this exact schema and refits the already reduced context if necessary, while the controller independently rejects stale/fenced updates. Existing LLM-only models keep their original schema and behavior. Both HTTP and Codex adapters preserve the optional update; the controller owns validation and execution. For maximum output reliability, update only what needs changing. Owner values and current facts always outrank stored interpretations.

## Memory and privacy

`006_cognition.sql` owns `cognitive_episodes`, `cognitive_states` and `cognitive_updates`; additive `007_cognitive_grounding.sql` owns reflection deduplication keys bound to the agent and retained outcome. Detail is encrypted with per-agent/per-episode or per-turn vault bindings. The controller does not merge memory across agents or reveal someone else's private contacts. Choosing cognition authorizes operational memory for that agent independently of observation consent. Operator inspection withholds cognitive detail when existing observation consent is off.

Episodes are bounded to 200 per agent and 3 KB per captured representation, with explicit coverage when larger observations are represented partially. Eviction preserves references supporting retained plans/beliefs/reflections, the newest 80 episodes, then important episodes within the total bound. Retrieval delivers at most five evidence items, three relevant beliefs and two recent reflections. Prompt fitting protects the current observation, newest receipt, whole persistent plan and both ordered candidates of any accepted Laya result. Whole optional prefetched action and read schemas are paged before continuity; tool names/permissions remain and an omitted shape is available through `fleet_action_schema` or `fleet_read_schema` within the existing decision allowance. Unprotected older episodes may be omitted with coverage. If additional subjective state is too large, at least the most relevant belief and latest reflection remain when present, with explicit counts of omitted items. Observed peer IDs remain available. If indispensable content cannot fit, fail before reserving a model call rather than drop accepted recall or raise the budget. Requested feedback, receipts and authoritative core facts retain their existing validation and explicit narrowing rules.

Large episodes retain typed peer/source identity and the actual message or receipt outcome before metadata; excerpts use UTF-8 boundaries and count JSON escaping. Current observations/receipts already delivered in the same decision can be referenced by source ID/date and the explicit environment/commandResults location rather than duplicated; historical requested recalls are never rebound to a fresh environment. Identical feedback action-kind lists reference the current list while retaining the correction schema/errors. Helper certificates/scores remain in turn history when omitted from a tight model prompt. Size-only diagnostics explain failures before any call is reserved. New PACT observations include a factual summary of buildings, builder status and resources; new receipts also record the decision's stated intention. Omitted facts remain unknown. Historical rows are not rewritten. Laya's preferred candidate precedes its other candidate in the actual evidence array, even when one is a receipt; the newest receipt is separately protected. Turn events record actual input bytes and whether the pair reached the prompt. Empty reviews and unchanged declarations are journaled idempotently but do not increment the state version or refresh evidence timestamps. Rejected local command shapes/versions remain execution feedback, not world-learning opportunities; protocol reflections remain in inspection/history but are withheld from model reflection continuity. Actual game receipts and later peer replies can support reflection. Already reflected outcomes are excluded from new analysis opportunities. One retained outcome can produce one reflection, including across restart, paraphrasing and eviction from the visible last eight; its deduplication key expires only with the retained source. Actual accepted counts and skipped duplicates are recorded separately from model-declared review labels. Legacy beliefs lacking basis/test/observed cue and reflections lacking an echoed observed-result review remain in encrypted history/inspection labeled legacy_unverified, and are withheld from model continuity. No historical row is rewritten during activation. The inspector shows actual saved judgments and accepted counts when observation consent permits it. The canonical review records a proposed analysis type or the model's abstention reason; an update label alone is not evidence of learning. Offered opportunity types and rejection selectors appear in encrypted turn diagnostics. An incoming statement already used as the basis of a belief does not continually restart the same future test. A later reply must also have been captured after the prediction was saved; a reply already seen cannot certify a new prediction.

Episodes and updates are purged after 30 days. Each plan/belief/reflection expires after 30 days without its own revision; a fresh unrelated update does not rejuvenate an old belief. Inactive state rows are also purged after 30 days. The journal's durable sequence preserves observation order when timestamps tie. Source availability is reported rather than fabricating forgotten evidence. Back up the normal Fleet database and matching vault key; do not restore old state over new gameplay to change modes.

The agent inspector shows plan goal/steps/status/reconsideration condition, each player's hypothesis/alternative/prediction/subjective confidence, reflections and retained source episodes. Turn history records which continuity/recall route was actually delivered and which updates were accepted/rejected. These declarations are not certifications of truth, game progress or human-like intelligence.

## Optional, evaluated Laya assistance

`recallAssist: "laya-recall-v1"` requires cognition. Its only role is **selective ordering of two already retrieved memory candidates** for the current question/plan. It never supplies commands, chooses strategic priorities, approves authority, changes beliefs or removes memory candidates. Current observations/receipts retain priority. Both candidates remain available to the LLM. If the helper is absent, slow, invalid or uncertain, Fleet records the exact fallback and retains deterministic recall.

Candidate text explicitly labels incoming peer speech, outgoing self speech or unknown direction before the quoted prose, including in Laya's 220-byte input. Unknown direction never supports a peer claim. Both helper and Nemotron see the direction; this does not turn selective recall accuracy into a gameplay guarantee.

Selected model: **`convaiinnovations/laya-typed-decisions`**, fixed revision **`e929ae5cf69bc34259cd2f95c9e91145b818b1f0`**, with **Laya 0.4.6**, CPU and two Torch threads. The full Python dependency selection is pinned in `laya-service/requirements.lock`. No GPU use or cloud model account is needed. Confidence is not assumed calibrated; the 0.65 cutoff is an empirically evaluated abstention rule for this limited recall task.

Initial unrestricted evaluation failed at 21/24. A first conservative selective configuration was correct on its accepted answers but accepted only 5/32, failing its coverage gate. After treating those as development data, a 0.65 cutoff and minimum 25% coverage were fixed before evaluating a new frozen 16-case validation set in both option orders. Final result: **18 accepted / 18 correct / 14 abstained out of 32**, against **8/18 correct** from lexical ordering on those same accepted cases. Development data had zero accepted errors. This is limited synthetic evidence supporting the optional recall helper; the small sample does not prove calibrated confidence, broad generalization, improved LLM play or better social intelligence. The actual checkpoint reports a temperature-clamp warning for 11+ options; this task uses exactly two and still makes no calibration claim.

The loopback service refuses startup without a passing certificate matching the exact frozen validation suite, runtime/revision/instructions/threshold and every checkpoint file digest. `laya-service/acceptance.json` records the source acceptance; the protected local certificate retains the installation's actual artifact proof. `POST /recall` accepts two bounded candidates and a bounded query only. It rejects other shapes, duplicate IDs, oversized bodies and browser-origin requests. Each Fleet request is bounded to three seconds and remaining turn time. The service logs no request bodies, keeps no player data files and accesses no game/LLM/database API.

## Local installation and verification

The evaluated recall cases are English. The client and service refuse non-ASCII material and use deterministic fallback rather than claim multilingual validation. ASCII alone does not establish English or guarantee relevance. Core memory supports Unicode and bounds captured excerpts by UTF-8 bytes without splitting characters.

Use a separate Python 3.12 environment and an explicit protected model directory. The downloaded weights are Apache-2.0 and must remain outside Git. From this repository:

```sh
uv venv --python 3.12 "$HOME/Library/Application Support/Fleet/cognition-laya"
uv pip install --python "$HOME/Library/Application Support/Fleet/cognition-laya/bin/python" -r laya-service/requirements.lock
```

Download the exact checkpoint revision with `huggingface_hub.snapshot_download`, passing `token=False`, into a protected directory. The installation on this Mac uses `$HOME/Library/Application Support/Fleet/laya-typed-decisions`. Generate a certificate against those local files; this uses fabricated fixtures only, with no game account or LLM inference:

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 "$HOME/Library/Application Support/Fleet/cognition-laya/bin/python" laya-service/verify_recall.py "$HOME/Library/Application Support/Fleet/laya-typed-decisions" "$HOME/Library/Application Support/Fleet/laya-recall-certificate.json"
```

A failed gate leaves Laya unused. Keep the failure evidence; do not mark a failed certificate passed or rewrite cases to conceal errors. The unrestricted diagnostic can be reproduced with `laya-service/evaluate.py` and a separate output path; do not overwrite a passing certificate with a diagnostic result.

Start the native helper only for the installation that will use it:

```sh
FLEET_LAYA_MODEL_PATH="$HOME/Library/Application Support/Fleet/laya-typed-decisions" FLEET_LAYA_CERT_PATH="$HOME/Library/Application Support/Fleet/laya-recall-certificate.json" "$HOME/Library/Application Support/Fleet/cognition-laya/bin/python" laya-service/server.py
```

It binds `127.0.0.1:8832`. Set `FLEET_LAYA_URL=http://127.0.0.1:8832` in that Fleet installation's protected environment, apply the additive migration and use the new source release. The later local deployment assignment installed the pinned console/worker and persistent native helper for the existing five agents; see its [deployment evidence](cognition-local-deployment-20261013.md). A container's loopback is its own namespace; this native setup is intended for the native Mac controller.

With the temporary helper running, `npx tsx scripts/verify-recall.ts` verifies actual HTTP accepted/abstained outcomes using the frozen synthetic cases. Python protocol/certificate tests run with `python -m unittest discover -s laya-service -p 'test_*.py' -v`. Normal Fleet tests use fake providers and only a separate `fleet_test` database.
